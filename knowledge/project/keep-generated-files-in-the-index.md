**`is_generated` と判定されたファイルも索引に入れる。** フラグは残すが、
**除外するのはレポートを作る段階**であって、索引を作る段階ではない。

理由: **誤陽性の代償が大きすぎる。** 索引から落とすと、そのファイルの symbol・呼び出し・
SQL・entry point が**まるごと消える**。誤って落とした 1 ファイルが、そこを通る
トレース全部を切る。レポート段階での除外なら、間違っていても後から気づけて戻せる。

## 誤陽性は理論上の心配ではない

HAPI FHIR で `is_generated` と判定された 7 ファイルを全部読んだ。**7 件とも誤陽性。**
生成コードは 1 つも無かった。

| ファイル | 引っかかった文字列 | 実体 |
|---|---|---|
| `ColumnTupleObject.java` | `sqlc` | `import ...sqlbuilder.SqlContext;` |
| `HapiFhirOracleTableExporter.java` | `sqlc` | `getSqlCreateStrings` |
| `MdmSearchExpandingInterceptor.java` | `auto-generated` | Javadoc の説明文「replaces the auto-generated CapabilityStatement」 |
| `StaticCapabilityStatementInterceptor.java` | `auto-generated` | 同上 |
| `ITermValueSetStorageSvc.java` | `@generated` | 1 メソッドの Javadoc に書かれた `@generated by ...` |
| 他 2 件 | `auto-generated` / `autogenerated` | 散文とテストの記述 |

**`GENERATED_MARKERS` の `"sqlc"` と `"jooq"` は裸の部分一致。**
`SqlContext` `getSqlCreateStrings` `SqlClause` `sqlCommand` に当たる。
**このツールの対象は SQL を書くコードベースなので、当たり続ける。**

`GENERATED_WEAK_MARKERS` の `"do not edit"` / `"do not modify"` も、
ライセンスヘッダや「勝手に触るな」の注意書きで当たる。

**効く場面:**

- `codewiki/index/scan.py` の `analyzable()` を触るとき。
  **`is_generated` で絞らない。** 言語で絞るだけ
- レポートやクエリを書くとき。`files.is_generated` で除外してよいが、
  **除外したことと件数を必ず出す。** 黙って消さない
- `GENERATED_MARKERS` を増やすとき。**部分一致になる短い語を足さない。**
  足すなら前後の語境界か、行頭からの位置を条件にする
- 「symbol が思ったより少ない」と言われたとき。真っ先にここを疑う
